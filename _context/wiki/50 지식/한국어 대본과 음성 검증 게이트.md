# 한국어 대본과 음성 검증 게이트

> [!info] 요약
> 대본·음성·렌더링 산출물은 `oozoofrog-mode`의 시제·종결어미·사료 고증 원칙과 함께 `pnpm lint:ko`, `pnpm typecheck`, `pnpm test`(16개 TypeScript 테스트 + Python 디노이즈 테스트), `endingDigest`·`.mp4.endings.json` 암호학적 가드, `check-video` 미디어 검증을 모두 통과해야 공개할 수 있다.
> 자동 전사(ASR)는 글자 일치만 확인하므로, 한국어 클론 음성의 `-다.` 끝모음 열림과 히스·치찰음 품질은 승인된 레퍼런스 오디오와 직접 대조 청취한다.

## 내용

### `oozoofrog-mode` 한국어 화법·시제·근거 규칙

- **시제와 화자 의도 분리 (`.agents/skills/oozoofrog-mode/SKILL.md`, `_context/editorial-direction.md`)**:
  - 발표자가 다음에 보여 줄 행동: 의지형 **`-겠습니다`** 사용 (예: `"오늘도 코드 한 줄을 함께 살펴보겠습니다."`, `"기록으로 들어가 보겠습니다."`).
  - 화면 속 코드가 지금 수행하는 동작: 현재형 **`-ㅂ니다 / -습니다`** 사용.
  - 과거의 제안·토론·릴리스 결정: 과거형 **`-았습니다 / -었습니다`** 사용.
  - 모든 구어 문장과 한국어 자막 문장은 평서형 **`-다.`**(또는 짧은 관찰 질문 `?`)로 맺는다.
- **2단 사료·컴파일러 고증 (`_context/historical-research.md`)**:
  - 과거 문법(`Swift 2.2`, `Swift 3.0`) 동작은 최신 컴파일러로 추측하지 않고 업스트림 릴리스 태그의 컴파일러 테스트(`Sort.swift.gyb`, `diag_c_style_for.swift`, `UIBezierPath.swift` 스냅샷)로 검증하며, 현행 Swift 코드는 로컬 Apple Swift `6.4.2`로 직접 실행해 확인한다. 기록이 남지 않은 결정 시점이나 인과관계는 추정하지 않고 공백으로 명시한다.

### 한국어 카피 정적 린트 (`pnpm lint:ko`)

`src/lib/korean-copy.ts`와 `scripts/lint-korean.ts`는 입력을 유니코드 `NFC`로 정규화한 뒤, 모든 `episodes/SE-*/script.json`(20개 인적 카피 키만 검사, `code` 블록은 제외)과 `episodes/unicode-1.0/`의 7개 파일(`narration.tsv`, `film.py`, `draw.py`, `produce.py`, `film_opening.py`, `motion/lines.json`, `motion/motion.js`)을 검사한다. `EpisodeScriptSchema.superRefine`과 `unicode-1.0/produce.py` 내부에서도 자동 실행된다.

| 금지 범주 | 차단되는 표현 예시 | 허용되는 구체적·리터럴 표현 예시 |
|---|---|---|
| 모호한 명사구 소제목 (`~에서/부터/으로 시작된 일`) | `"글꼴에서 시작된 일"` | `"제록스의 중국어 글꼴 개발"`, `"서울에서 시작된 일정"`, `"서울에서 시작된 일주일"` |
| 모호한 공간 대명사 (`~자리` 표현 5종) | `"번호가 들어가는 자리는"`, `"들어가느자리"`, `"한 획이 되돌아온 자리"`, `"행과 열이 만나는 자리"`, `"두 글자에 서로 다른 자리를 주었습니다."` | `"76행 73열"`, `"두 글자의 번호가 달랐습니다."`, `"획의 가장자리"`, `"소수점 셋째 자리"` |

### 자동화 테스트 스위트 (`pnpm test` 16개 + Python 1개)

1. **`tests/ending-check.test.ts` (3개 테스트)**:
   - 따옴표가 닫히는 한국어 평서문(`'값을 건넵니다.”'`)의 `needsVowelRelease === true` 판별 및 질문·영문 예외 처리.
   - 대본 텍스트 또는 MP3 바이트 변경 시 `endingDigest` 무효화 및 교체된 `.mp4`에 대한 `checkRenderedFile` 차단.
   - `manifest.json` 누락 또는 `endingDigest` 없는 `qwen3-clone` 장면 거부.
2. **`tests/korean-copy.test.ts` (4개 테스트)**:
   - 모호한 `자리` 표현 차단 및 `가장자리`·`소수점 셋째 자리`·`76행 73열` 허용.
   - `shortsScenes.0.shortSpeech.0.text` 정확한 JSON 경로 보고 및 `code.code` 무시.
   - `episodes/SE-0006/script.json`의 `chapterTitle` 변조 시 스키마 검증 실패 확인.
   - `"글꼴에서 시작된 일"` 차단 및 `"제록스의 중국어 글꼴 개발"`·`"일정"`·`"일주일"` 허용.
3. **`tests/pipeline.test.ts` (9개 테스트)**:
   - 제안서 번호 정규화(`normalizeProposalId`), Swift 구문 토크나이저(`tokenizeSwift`), SRT/WebVTT 왕복 파싱, `SAMPLE_SCRIPT` 타임라인·챕터 생성, 한·영 `speech`/`shortSpeech` 격리, `codeReveal` 구조 검증, 질문 뒤 `0.65초` 휴지 및 문장 중간 연속 큐(`0초`), `long`/`short` 독립 단계 추적(`formatStage`), 판본별 핀포인트 `repeatedTargets` 집계 검증.
4. **`tests/test_voice_denoise.py` (Python `unittest` 1개)**:
   - `24kHz` 가우시안 히스 + `180 Hz` 유성음 신호에 `denoise_voice` 적용 시 (1) 입출력 샘플 길이 완벽 일치, (2) 무음 도입부 노이즈 `> 3 dB` 감쇠, (3) 유성음 꼬리 레벨 변화 `< 0.5 dB`, (4) 음성 시작 시각 오차 `5 ms`(`rate // 200`) 이내 유지를 검증한다.

### 오디오 히스·끝모음·길이 일치 검증 게이트

- **종결 모음 및 파일 무결성 (`src/services/ending-check.ts`)**: `pnpm evo render`와 `pnpm evo upload`가 `manifest.json`의 `endingDigest`와 `<video>.mp4.endings.json`을 대조해 강제 정렬 모음 릴리스를 거치지 않았거나 재렌더링 전 수정된 산출물을 차단한다([[Swift Evolution 영상 제작 파이프라인]] 참고).
- **렌더링 미디어·자막 일치 (`src/services/check-video.ts`)**: `pnpm evo check-video <id>`가 (1) `manifest.json`과 `script.json` 장면 수·순서, (2) 모든 `termNotes`·`people`·`codeSteps`·`codeReveal.answerCue`의 자막 큐 존재 여부, (3) `subtitles.srt`와 매니페스트 큐의 바이트 일치, (4) `ffprobe` 기준 해상도(`1920x1080` / `1080x1920`)와 오디오·비디오 스트림 길이 차이(`<= 2 / fps`초), (5) `ffmpeg volumedetect` 기준 `max_volume >= -80 dB`를 검사한다.
- **ASR 재전사 및 사람 귀 청취 검수**: 새로 합성한 문장은 `qwen3-asr`로 전사해 오발음(예: `SE-0005`의 `"남곤"` -> `"남본"`, `unicode-1.0`의 `"토토어가"` -> `"토투어"`)을 잡고, 최종 음질(`다.`의 `ㅏ` 모음 열림, 들숨 간격, 히스 억제 후 치찰음, 배속된 쇼츠 발음)은 승인된 기준 샘플(`episodes/SE-0001/out/vowel-review/SE-0001-ending-sample.m4a`, `episodes/SE-0003/out/new-reference-full-vowel.m4a`, `episodes/SE-0001/out/vowel-review/noise-review/opening-retake.wav`)과 같은 음량에서 비교 청취한다.

## 주의할 점

- 자막 싱크를 검증할 때는 렌더링 전 `script.json` 추정치만 믿지 말고, 최종 내보낸 `.mp4`에서 디코딩한 실제 오디오 파형과 대조해야 한다(`SE-0005` 제작 당시 3월 3일 큐에서 약 `570ms` 밀림을 잡아 수정했고, `SE-0006`에서는 전 문장 오차 `23ms` 이내를 확인함).
- `qwen3-clone`이 복합 명사나 한자어 경계에서 연음을 과하게 뭉개면 화면 자막(`caption` 또는 `ko`)은 그대로 두고 발음용 텍스트(`speech`)에만 쉼표(`,`)를 넣어 운율 경계를 만든다.

## 확인 방법

```sh
pnpm lint:ko && pnpm typecheck && pnpm test && python3 -m unittest tests/test_voice_denoise.py
pnpm evo check-video SE-0006 --format both
```
