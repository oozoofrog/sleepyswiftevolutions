# 유튜브와 인스타그램 게시 절차 및 장애 대응

> [!info] 요약
> 외부 플랫폼 게시 전에는 반드시 로컬 영수증과 실제 채널·프로필 목록을 먼저 대조해 중복 업로드를 차단한다.
> YouTube Data API에서 `429 Too Many Requests`나 `403 quotaExceeded`가 발생하면 영상을 다시 올리지 않고, 이미 발급된 `videoId`를 Chrome YouTube Studio에서 열어 누락된 썸네일·자막·재생목록만 마저 설정한다.
> 인스타그램 웹 릴스는 SRT 업로드가 없고 기본 비율이 `1:1`로 열리므로, `ffmpeg-full`로 한국어 자막을 번인한 `-ko.mp4`를 준비해 `자르기 선택` -> `9:16` 전환을 2단계로 실행하고 캡션은 클립보드 붙여넣기(`수정 > 붙여넣기`)로 입력한다.

## 내용

### 1. 게시 전 중복 방지 사전 점검

- **YouTube**: `videos.insert` 호출 전에 인증 채널이 `UCCtGyB0lbnsT0ES0Yuwhwjg`인지 확인하고, `data/state.json`(또는 `episodes/unicode-1.0/out/upload-receipt.json`)과 실제 채널 업로드 목록을 비교한다. 업로드 직후 쇼츠가 `processing` 상태일 수 있으므로 ‘업로드 수락’과 ‘HD 처리 완료(`succeeded`)’를 분리해 같은 `videoId`를 재조회한다.
- **Instagram Reels**: 업로드 시작 전 `https://www.instagram.com/oozoofrog/` 프로필의 기존 게시물 수와 `/reels/` 탭을 확인하고, 2단계 인증(2FA) 창이 뜨면 즉시 조작을 멈추고 사용자의 직접 로그인 완료 응답을 받은 뒤 진행한다.

### 2. YouTube Data API `429` · `403 quotaExceeded` 발생 시 Chrome Studio 이어받기

`videos.insert`로 영상 본체가 올라간 뒤 `thumbnails.set`에서 `429 Too Many Requests`가 나거나 `captions.insert`·`captions.list`에서 일일 할당량 초과(`403 quotaExceeded`)가 발생할 때의 표준 복구 절차다(`SE-0004`, `SE-0002` 쇼츠, `unicode-1.0` 공개에서 검증됨).

1. **재업로드 금지**: 이미 발급된 `videoId`를 영수증(`data/state.json` 또는 `upload-receipt.json`)에 보존하고 절대 MP4를 다시 올리지 않는다.
2. **Chrome YouTube Studio 직접 제어**: `https://studio.youtube.com/video/<videoId>/edit`(세부정보·썸네일·재생목록·공개 상태)와 `https://studio.youtube.com/video/<videoId>/translations`(`ko`, `en`, `ja`, `zh-Hans` SRT 업로드)에서 실패한 항목만 채운다.
3. **`mac-cu` 제어 시 주의점**: Chrome 헬퍼 프로세스들이 `"Google Chrome"` 이름을 공유해 브라우저 확장 모드가 충돌할 수 있으므로, `com.google.Chrome` 앱 접근성 모드(`get_app_state` / `act`)로 직접 구동한다.
4. **사후 재검증**: 저장 직후 스튜디오 페이지를 다시 열어 썸네일 반영, 4개 언어 자막 `게시됨`, 재생목록 소속, `공개` 상태를 눈으로 확인한다. `upload.ts --verify-only`는 쿼터 소진 시 `captions.list` 예외를 잡아 영수증 기록과 대조한다.

### 3. 인스타그램 웹 릴스 게시 절차와 5가지 UI 함정 대응

1. **사이드카 SRT 미지원과 `ffmpeg-full` 한국어 자막 번인**:
   - 인스타그램 웹은 SRT 자막 트랙 업로드를 지원하지 않는다. 기본 Homebrew `ffmpeg`에는 `libass`가 없으므로 반드시 `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`를 써서 하단 안전 여백에 한국어 자막을 구운 `-ko.mp4`를 준비한다.
   - 어두운 배경(`SE-0004` 등 Swift Evolution 쇼츠) 번인 명령 규격:
     ```sh
     /opt/homebrew/opt/ffmpeg-full/bin/ffmpeg -y \
       -i episodes/SE-0004/out/SE-0004-9x16.mp4 \
       -vf "subtitles=episodes/SE-0004/audio/short/subtitles.srt:force_style='FontName=Apple SD Gothic Neo,Bold=1,FontSize=9,PrimaryColour=&H00F5F2EC,OutlineColour=&H26100F0E,BackColour=&H26100F0E,BorderStyle=3,Outline=3,Shadow=0,Alignment=2,MarginL=20,MarginR=20,MarginV=38'" \
       -c:v h264_videotoolbox -b:v 8M -c:a copy -movflags +faststart \
       episodes/SE-0004/out/SE-0004-9x16-ko.mp4
     ```
   - 밝은 종이 배경(`unicode-1.0/produce.py`)은 `FontSize=13`, `PrimaryColour=&H00252A27`, `OutlineColour=&H00F8F8F7`, `MarginV=43`을 사용한다.
2. **`1:1` 기본 자르기 함정 (반드시 2단계 분리 클릭)**:
   - 웹 작성기는 세로 영상을 불러와도 기본으로 `1:1` 정사각형 자르기를 적용한다.
   - `mac-cu`에서 `자르기 선택` 버튼 클릭과 `9:16 세로 방향 자르기 아이콘` 클릭을 한 번의 `act` 배치로 묶으면, 팝오버가 열리기 전 스냅샷 인덱스를 참조해 엉뚱한 요소(`EmptyGroup`)를 누르게 된다. 반드시 (1) `자르기 선택` 클릭 후 `0.4초` 대기 -> 새 접근성 트리 조회 -> (2) `9:16 세로 방향 자르기 아이콘` 클릭의 2단계로 나눈다.
3. **맞춤 커버(`1080x1920`) 및 파일 대화상자 인덱스 차이**:
   - 동영상 선택 `open-panel`에는 왼쪽 사이드바에 `동영상` 항목이 들어가고 이미지 커버 선택 `open-panel`에는 빠지므로 버튼 인덱스가 `4`만큼 달라진다. 하드링크 스테이징 폴더(`out/reels-staging/`)에 영상·커버 쌍을 모아 두고 매 단계 새 트리를 읽어 클릭한다(게시 완료 후 스테이징 폴더 삭제).
4. **Lexical 캡션 편집기의 `set_value` 무시 대응**:
   - 캡션 입력창(`TextArea "캡션 추가..."`)은 Lexical 기반이라 접근성 `set_value`를 호출해도 내부 글자 수가 `0/2200`으로 남는다. `pnpm lint:ko`를 통과한 캡션을 `LANG=ko_KR.UTF-8 pbcopy`로 복사한 뒤 입력창 포커스 후 `menu: ["수정", "붙여넣기"]`를 실행하고, 글자 수 카운터(`XXX/2200`)가 `0`보다 큰지 확인한 다음 공유한다(작업 종료 후 클립보드 초기화).
5. **교차 게시 비활성화**: Facebook 자동 교차 게시 토글은 `OFF`로 유지한다.

### 4. 플랫폼별 세로 영상 길이 제한과 `scookie*` 대응

- **길이 상한**: YouTube Shorts는 최대 **`180초(3분)`** 가 엄격한 상한이다. Instagram Reels는 앱 최대 20분(API 15분)까지 허용하지만 비팔로워 추천 노출 기준선이 동일하게 **`180초(3분)`** 다.
- **`scookie*` 단문 분리 패턴**: `unicode-1.0`에 2문장짜리 쿠키 4장면(`cookiever`~`cookiemost`)을 그대로 붙였을 때 쇼츠 길이가 약 `195.0초`로 `180초` 상한을 넘자, `narration.tsv`에 1문장 요약 키(`scookiever`~`scookiemost`)를 별도로 두고 `film.py`에서 `if key.startswith('scookie'): key = key[1:]`로 동일한 시각 카드를 공유하며 `credits`를 `2.5초`로 줄여 `170.63초`로 맞췄다.

## 주의할 점

- 번인 자막 사본(`-ko.mp4`)을 만든 뒤에는 반드시 코드나 하단 캡션(`folio`)이 많은 구간 프레임을 추출해 자막 상자와 본문 요소가 겹치지 않는지 시각 검수한다.
- YouTube API 일일 할당량은 태평양 표준시 자정(한국 시간 오후 4시/5시)에 초기화되지만, 이미 올라간 `videoId`가 있다면 초기화를 기다리거나 예약 작업을 걸어 두는 대신 Chrome YouTube Studio에서 당일 즉시 마무리한다.

## 확인 방법

- 게시된 전체 링크 및 영수증 대조: [[전체 공개 영상과 릴스 목록]]의 확인 명령(`pnpm evo status`, `upload.ts --verify-only`, `data/instagram-reels-receipt.json`)을 실행한다.
- 번인된 MP4의 자막 겹침 점검: `ffmpeg -ss 15 -i <file>-ko.mp4 -frames:v 1 /Volumes/eyedisk/tmp/frame-check.png` 추출 후 화면 여백을 확인한다.
