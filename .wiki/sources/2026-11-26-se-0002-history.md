# SE-0002 source notes

[The first proposal commit](https://github.com/swiftlang/swift-evolution/commit/604c4f6dea75) dates to 2015-11-04. [The compiler change](https://github.com/swiftlang/swift/commit/983a674e0ca35a85532d70a3eb61e71a6d024108) made curried function declaration syntax an error on 2016-01-21. [Swift 3.0 shipped](https://www.swift.org/blog/swift-3.0-released/) on 2016-09-13.

The [proposal](../../episodes/SE-0002/proposal.md) removes consecutive parameter lists from a function declaration. A function can still return a closure. The episode uses addition to show the distinction. The local Swift interpreter returned 5 for both addTwo(3) and add(2)(3).

The [episode research notes](../../episodes/SE-0002/research.md) trace the accepted first snapshot, PR 20's example correction and the February wildcard discussion to specific claims and scenes.

The review of the [Joe Groff profile](https://github.com/jckarter), the [Davide De Franceschi profile](https://github.com/DeFrenZ), Wikimedia Commons and Openverse did not identify a portrait of either contributor with verified commercial reuse terms. Both appear by name and GitHub handle when mentioned.
