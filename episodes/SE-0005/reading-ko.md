# SE-0005 · to가 괄호 안으로 들어갔다

**낭독·연출 대본**　|　Swift 3.0 · Objective-C API를 Swift로 가져올 때 이름이 바뀌는 과정

경로 예시에서는 목적지를 (10, 20)으로 고정한다. 각 장면의 시대 표기를 코드와 함께 보여 준다. 인물 소개에는 검증된 프로필의 이름과 역할을 쓴다.

## 본편 · 16:9

### 1. Objective-C와 UIKit

**화면**　Objective-C에서 그림의 시작점을 지정하는 호출을 보여 준다. Swift를 소개할 때 `path`와 `end`가 새 위치로 이동한다. 대괄호와 콜론은 사라지고, Swift 2의 점과 괄호가 들어온다. 좌표는 (10, 20)으로 유지한다.

Objective-C · UIKit

```objc
CGPoint end = CGPointMake(10, 20);
[path moveToPoint:end];
```

Swift 2 · UIKit

```swift
let end = CGPoint(x: 10, y: 20)
path.moveToPoint(end)
```

**낭독**

오늘도 코드 한 줄을 함께 살펴보겠습니다.

스위프트가 나오기 전부터 개발자들은 오브젝티브 씨라는 프로그래밍 언어로 아이폰 앱을 만들었습니다.

앱 화면에 글씨나 그림을 띄울 때는 애플이 제공하는 도구 모음인 유아이킷을 썼습니다.

화면의 둘째 줄은 그림을 어디서 시작할지 정하는 명령입니다.

스위프트로 앱을 만드는 개발자도 유아이킷의 같은 기능을 쓸 수 있었습니다.

첫 줄에서 이미 점을 만들었는데, 둘째 줄의 이름에 점이라는 말이 또 나옵니다.

그래서 이번 제안은 겹치는 말을 줄이고, 값을 어디에 쓰는지 드러내도록 이름을 가져오는 규칙을 바꾸려 했습니다.

### 2. Swift 2의 그리기 코드

**화면**　“첫 줄은 점 하나를 만듭니다”에서 `CGPoint`의 `Point`가 살짝 커졌다 돌아온다. “둘째 줄을 실행하면”에서는 `moveTo`가 같은 방식으로 움직인다. 기존 코드가 폭을 줄이며 왼쪽으로 움직인다. 빈 모눈종이가 코드 뒤에서 오른쪽으로 드러난다. “점”에서 좌표와 시작점이 드러나고, “그 점으로”에서 연필이 내려와 멈춘다. 이 장면에서는 선을 긋지 않는다.

Swift 2 · UIKit

```swift
let end = CGPoint(x: 10, y: 20)
path.moveToPoint(end)
```

**낭독**

첫 줄은 점 하나를 만듭니다.

둘째 줄을 실행하면 경로의 현재 위치가 그 점으로 옮겨갑니다.

둘째 줄의 이름에서 단어 하나를 빼도 뜻이 통합니다.

**읽는 속도와 쉼**　첫 문장 뒤에 숨을 쉽니다. 마지막에는 코드를 읽을 시간을 둡니다.

### 3. 2015년 12월 초안

**화면**　두 패널의 첫 줄과 좌표를 맞춘다. `moveToPoint(end)`에서 마지막 `Point`가 빠진 자리를 보여 준다. 공동 제안자 두 사람은 이름을 읽을 때 소개한다.

Swift 2 · UIKit

```swift
let end = CGPoint(x: 10, y: 20)
path.moveToPoint(end)
```

2015년 12월 · 제안서 예시

```swift
let end = CGPoint(x: 10, y: 20)
path.moveTo(end)
```

**낭독**

점을 뜻하는 말이 두 번 나옵니다.

더그 그레거와 데이브 에이브러햄스는 오브젝티브 시의 메서드를 스위프트로 가져올 때 이런 반복을 줄이자고 제안했습니다.

두 사람이 십이월 제안서에 적은 예시에서는 맨 끝의 포인트만 빠졌습니다.

어디로 움직이는지 알려 주는 투는 아직 여는 괄호 앞에 있습니다.

**읽는 속도와 쉼**　초안이라는 말을 또렷하게 읽습니다. 두 번째 표기를 충분히 보여 줍니다.

### 4. 2016년 1월 공개 리뷰

**화면**　`enumerateObjectsWithOptions`에서 동작과 옵션을 차례로 짚는다. 라데크가 제시한 `enumerateObjects(options: …)`를 보여 준 뒤 더그의 1월 실험으로 넘어간다.

리뷰에서 비교한 이름 · 발췌

```swift
enumerateObjectsWithOptions
```

리뷰어가 제시한 표기 · 발췌

```swift
enumerateObjects(options: …)
```

**낭독**

이듬해 일월 공개 리뷰에서 라데크 피에트루셰프스키는 목록을 훑는 메서드에 주목했습니다.

이 메서드는 목록의 항목을 하나씩 처리합니다.

옵션은 그 순서나 방식을 지정합니다.

그는 옵션이라는 말을 괄호 안에 두면 그 뒤에 넣을 값의 쓰임을 바로 알 수 있다고 설명했습니다.

더그 그레거는 이 의견을 듣고 이름을 위드에서 나누는 규칙을 시험했습니다.

그 규칙을 적용해 보니, 코코아 에이피아이 파일 이백한 개에서 이름이 달라졌습니다.

**읽는 속도와 쉼**　메서드가 하는 일과 옵션의 역할 사이에서 한 번 쉽니다.

### 5. 2016년 2월 설계 논의

**화면**　12월 초안과 Swift 3 코드를 나란히 둔다. “전치사를”이 들리면 초안에서 앞서 짚은 `To`가 살짝 커졌다 돌아온다. 이어 “값과”가 들리면 Swift 3의 인자 레이블 `to:` 뒤에만 배경을 넣는다. 다음 문장에서 더그의 컴파일러 변경 날짜를 띄운다.

2015년 12월 · 제안서 예시

```swift
let end = CGPoint(x: 10, y: 20)
path.moveTo(end)
```

Swift 3 · UIKit

```swift
let end = CGPoint(x: 10, y: 20)
path.move(to: end)
```

**낭독**

이월에는 논의가 방향이나 관계를 나타내는 다른 단어로 넓어졌습니다.

데이브 에이브러햄스는 설계 지침 작업 그룹에서 여러 호출을 읽어 본 결과를 전했습니다.

작업 그룹은 전치사를 그 뒤에 오는 값과 함께 괄호 안에서 읽는 편을 택했습니다.

다음 날 더그 그레거가 컴파일러에 이 규칙을 반영했습니다.

이제 괄호 앞에는 이동한다는 동작이 남고, 괄호 안에는 어디로 이동하는지가 보입니다.

**읽는 속도와 쉼**　초안의 괄호를 보여 준 뒤 전치사를 설명하는 문장에서 새 표기로 바꿉니다.

### 6. 배열 이름 앞의 NS

**화면**　`Array`를 강조할 때는 복사한 쪽에만 항목이 늘어나는 예를 읽는다. `NSMutableArray`의 `Mutable`을 강조할 때는 두 변수가 같은 객체를 가리키는 예를 읽는다. 마지막에 3월 3일 채택 결정을 표시한다.

Swift와 Foundation · 타입 이름

```swift
Array
NSMutableArray
```

**낭독**

이름을 줄였다가 오히려 차이를 알아보기 어려워지는 경우도 있었습니다.

스위프트 배열은 다른 변수에 대입한 뒤 한쪽에 항목을 더해도 다른 쪽의 항목 수는 그대로입니다.

그런데 두 변수가 같은 가변 배열 객체를 가리키면 한쪽에 더한 항목이 다른 쪽에서도 보입니다.

데이브 에이브러햄스는 이름 앞의 엔에스를 떼면 두 배열이 이처럼 다르게 동작한다는 점을 놓치기 쉽다고 지적했습니다.

삼월 삼일 채택 공지에서 파운데이션의 접두사를 없애는 문제는 별도 제안으로 남겼습니다.

**읽는 속도와 쉼**　두 변수에서 보이는 항목 수의 차이에 힘을 줍니다.

### 7. Swift 3.0의 호출

**화면**　연필이 첫 장면과 같은 좌표에 닿을 때는 종이를 비워 둔다. 다음 대사에서 꼭짓점 배열을 따라 선분이 하나씩 나타난다. 완성된 종이비행기를 옆에 두고 시작점을 다시 짚는다. 마지막 문장을 읽는 동안 `to: end`를 화면에 남긴다.

Swift 3 · UIKit

```swift
let end = CGPoint(x: 10, y: 20)
path.move(to: end)
```

꼭짓점을 잇는 장면의 코드

```swift
path.move(to: end)
for point in corners {
    path.addLine(to: point)
    path.stroke()
}
```

**낭독**

그해 구월에 출시된 스위프트 삼에서 첫 장면의 코드를 다시 보겠습니다.

경로의 현재 위치는 처음과 같은 점입니다.

연필을 시작점에 옮겨 놓으면 종이에는 아직 선이 없습니다.

이제 종이비행기의 꼭짓점을 차례로 잇고, 선분을 더할 때마다 경로를 그려 보겠습니다.

점을 뜻하는 말을 되풀이하지 않고도 목적지를 알아볼 수 있게 하자는 제안이었습니다.

**읽는 속도와 쉼**　목적지라는 말을 한 번 짚고 마지막 코드 위에서 숨을 마칩니다.
