# SE-0005 · Where did the “to” in moveToPoint go?

A developer migrating a drawing app to Swift 3 had to change the line that positions a path. The same Objective-C selector, `moveToPoint:`, appeared under different Swift names. The point type explains what the argument is. The preposition explains how the operation uses it. The December proposal and the public review let us follow the two decisions separately.

| Evidence | Swift call with the same point | What changed |
| --- | --- | --- |
| Swift 2 UIKit interface | `path.moveToPoint(end)` | The method name carries both the direction and the type. [Historical UIKit interface, line 21](https://github.com/swiftlang/swift-3-api-guidelines-review/blob/ebf5d8fddc4d/Platforms/iOS/UIKit/UIBezierPath.swift#L21) |
| December 2015 proposal | `path.moveTo(end)` | The example removes the type word. The preposition stays on the method name. [First revision](https://github.com/swiftlang/swift-evolution/blob/4444d23e7f1f/proposals/0005-objective-c-name-translation.md) |
| Revised Swift 3 interface | `path.move(to: end)` | The caller reads the direction with the destination. [Review revision](https://github.com/swiftlang/swift-evolution/commit/bf2e4c4bcb1a) · [Updated UIKit interface, line 21](https://github.com/swiftlang/swift-3-api-guidelines-review/blob/64e3132a6a38/Platforms/iOS/UIKit/UIBezierPath.swift#L21) |

## What was under review

Swift programmers used UIKit and Foundation through the Clang importer. A change to its default naming rules affected calls across frameworks and mixed-language apps. SE-0023 defined the design guidelines, SE-0006 applied them to Swift's standard library, and SE-0005 applied them to imported APIs. Reviewing the three together let participants test a naming principle against code people actually called. Authors could supply a Swift-specific name in an Objective-C header when the automatic rule produced a poor result. [December 3 public introduction](https://www.swift.org/blog/swift-3-api-design/) · [Proposal and reviewer notes](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0005-objective-c-name-translation.md)

## Episode use and verification

Open on `let end = CGPoint(x: 10, y: 20)`. Keep the destination on screen through all three historical spellings. Using `move` sets the path's current point and starts a subpath. A subsequent line operation would draw a segment. The Short can end at the change from `moveTo(end)` to `move(to: end)`. In the full episode, contrast the type word that could disappear with the Foundation prefix that still helped readers anticipate copying and sharing. This is an editorial connection. Radek’s direct influence is documented for the January prototype. The broader February rule has its own working-group and compiler records.

Verification on 2026-11-27 used the two pinned UIKit interface snapshots above. The installed Objective-C header still declares `moveToPoint:`. A small UIKit function that calls `path.move(to: CGPoint(x: 10, y: 20))` and returns `path.currentPoint` was checked with the installed iOS Simulator SDK and Apple Swift 6.4.2. Historical spellings were checked against source records. No Swift 2 or Swift 3 binary was executed. The early commit and the December public article establish the surviving written origin. Earlier private deliberations remain undocumented here.

## Drawing example in the revised cut

The episode’s paper airplane is an original illustration. The opening and closing use the same starting point, (10, 20). The shape uses the ordered `drawingCorners` in [the scene data](script.json). In a UIKit drawing context, `move(to:)` starts the subpath at that point. Each loop iteration adds a segment with `addLine(to:)` and paints the current path with `stroke()`. The frame animation slows down the pencil to make each segment visible. The grid, pencil and start marker are explanatory overlays.

## Why Objective-C appears before the Swift example

Apple’s archived introduction describes Objective-C as an object-oriented programming language used to write iOS and OS X software. UIKit supplied interface and drawing features to apps. In this example, Objective-C code sends the `moveToPoint:` message to a path. Swift 2 exposes the same operation as `path.moveToPoint(end)`. The proposal addressed how the compiler presented imported names to Swift callers. In his January 2016 account, Dave Abrahams explains why inconsistent naming between Cocoa and the Swift standard library made even familiar operations harder to predict. The episode introduces that practical problem before presenting the draft and the released spelling.
